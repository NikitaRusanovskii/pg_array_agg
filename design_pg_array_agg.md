# Дизайн-документ расширения pg_array_agg

#### Наименование: pg_array_agg

Реализует агрегатные функции, принимающие на вход массив и возвращающие скаляр.

## Постановка задачи

### Общие требования

1. Расширение должно быть реализовано на языке C.
2. Функции должны работать с одномерными массивами (пустой массив с `ndim = 0` считаем одномерным, пустым) и двумерными массивами (для функций с предикатами — обход в порядке расположения в памяти) базовых типов PostgreSQL. В случае некорректных входных данных должно выводиться сообщение об ошибке.
3. Для предикатов рассматриваются только простые условия: `>`, `>=`, `<`, `<=`, `==`, `!=`, операция `%` (остаток от деления) и равенство `=`.
4. Для предикатов используется следующий синтаксис: `x op Const`, `x op Const = Const`, где `x` — переменная, обозначающая элемент массива. Пустой предикат (`''`) используется, когда для соответствующей размерности ничего вычислять не требуется. Константа может быть числовой и строковой; в случае строки она должна заключаться в двойные кавычки: `x op "str"`. Для строковых констант определены только операции равенства и неравенства.
5. Значение `NULL` должно обрабатываться корректно, `NULL != NULL`.
6. Функции должны быть `IMMUTABLE`.
7. Для каждой функции необходимо реализовать набор тестов, проверяющий её работу на корректных и некорректных данных, со всеми возвращаемыми функцией вариантами ошибок.
8. Для каждой функции необходимо описать существующие ограничения, в том числе возможные диапазоны (значения) входных и выходных данных.
9. Для каждой функции необходимо провести серию замеров, собрать статистику и построить график зависимости времени выполнения от объёма входных данных.

### Предикаты

Тип: `text`.

Доступные операторы: `<`, `>`, `<=`, `>=`, `==`, `!=`, `=`, `%`.

Доступные синтаксические конструкции:

- `{variable} {operator} {const}`
- `{variable} {operator} {const} = {const}`

К строковым типам данных применимы только `==` и `!=`.

`variable` может иметь произвольное строковое имя, на результат имя не влияет. Имена должны отличаться для разных измерений, если поддержка измерений будет введена.


Поведение обработки предикатов при граничных случаях

| Граничный случай | Пример | Поведение |
|---|---|---|
| Пустой предикат или строка из пробелов | `''` | Обработка пропускается |
| Отсутствует обязательный компонент выражения | `x >, > 10, x` | Синтаксическая ошибка |
| Нарушен порядок компонентов или присутствуют лишние элементы | `x 10 >, x > 10 xyz` | Синтаксическая ошибка |
| Использован неподдерживаемый оператор | `x <> 10` | Ошибка |
| Некорректная запись константы | `x > 1.2.3` | Ошибка |
| Константа не представима в целевом типе | Чрезвычайно большое число | Ошибка преобразования |
| Тип константы несовместим с типом элементов массива | `x > "abc"` для числового массива | Ошибка |
| Некорректное оформление или экранирование строки | `x = "abc` | Ошибка |
| Пробелы внутри или вокруг компонентов выражения | `x > 10` | Стандартное поведение, пробелы не учитываются|
| Некорректная форма `{variable} {operator} {const} = {const}` | `x > 10 =, x > 10 = abc` | Ошибка |
| Арифметическая ошибка при вычислении выражения | `x % 0 = 0` | Ошибка. Отработается при выполнении функции |
| NaN, Infinity, -Infinity, -0.0 | `x = 'NaN'` | Обрабатываем по правилам соответствующего типа |
| Чрезмерная длина предиката или константы | Очень длинная строка | т.к. предикат типа `text`, то обрабатывается корректно. Однако только если приведение константы к целевому типу отработает корректно|

Числовые типы: `smallint`, `integer`, `bigint`, `decimal`, `numeric`, `real`, `double precision`.

Строковые типы: `character varying(n)`, `varchar(n)`, `character(n)`, `char(n)`, `text`.

## Объяснение некоторых решений:
1) Использование итераторов. Это позволит обрабатывать большие массивы без развёртывания их в оперативной памяти.
2) Универсальные функции (напр. universal_cmp). Позволяют упростить функции расширения, повысив читаемость. Всю логику, связанную с обработкой разных типов выносим в utils.
3) Механизм кэшированных регулярных выражений PostgreSQL для повышения производительности по сравнению с простыми regex
4) Для обеспечения максимальной совместимости всё что можно реализовать через API PostgreSQL, реализуется через него.


## Подробные спецификации функций

В сигнатурах ниже `predicate` - обозначение параметра SQL-типа `text`, который разбирается расширением. Все функции объявлены `IMMUTABLE`.

### Общие правила обработки

- Для `array_product`, `array_sum`, `array_avg`, `array_min` и `array_max` аргумент-массив `NULL` или любой элемент массива `NULL` приводит к результату `NULL`.
- Для `array_count`, `array_count_if`, `array_all`, `array_any` и `array_none` элементы массива `NULL` пропускаются.
- Пустой массив с `ndim = 0` и пустой массив с `ndim = 1` рассматриваются как пустые одномерные массивы. Для функций, поддерживающих только одномерный массив, `ndim > 1` вызывает ошибку, в том числе для пустого массива. *На данный момент все функции работают только с 0 и 1 мерными массивами, однако реализация предполагает лёгкое расширение до поддержки необходимых размерностей*
- Неожиданный тип элемента, включая пользовательские типы, вызывает ошибку. Для арифметических функций, функций сравнения ожидаются `smallint`, `integer`, `bigint`, `decimal`, `numeric`, `real`, `double precision`. Для функций предикатов также ожидаются `character varying(n)`, `varchar(n)`, `character(n)`, `char(n)` и `text`. *Также можно реализовать их для функций сравнения* 
- Переполнение и деление на ноль вызывают ошибку. Несовместимые типы при сравнении или выполнении операции вызывают ошибку.
- Синтаксис предиката: `x op Const` или `x op Const = Const`. Операторы: `<`, `>`, `<=`, `>=`, `==`, `!=`, `=`, `%`. Для строк определены только равенство и неравенство. Строковая константа задаётся в двойных кавычках в синтаксисе предиката (`x op "str"`); экранирование не поддерживается. Лексическая и синтаксическая ошибки разбора предиката приводят к ошибке функции.

### `array_product`

**Общая сигнатура функции:** `array_product(anyarray) -> numeric`

**SQL-сигнатура:** `array_product(anyarray) RETURNS numeric`

**C-сигнатура:** `Datum array_product(PG_FUNCTION_ARGS)`

**Параметры входного массива:**
- Длина: произвольная.
- Число измерений: `ndim = 0` или `ndim = 1`.
- Типы элементов: `smallint`, `integer`, `bigint`, `decimal`, `numeric`, `real`, `double precision`.
- Функция `STRICT`; массив или элемент `NULL` приводит к `NULL`.

**Алгоритмическое решение и пояснение.**

Массив обходится итератором. Каждый элемент приводится к `numeric`, после чего накапливается произведение `res *= element` с использованием `numeric_mul`. Итератор позволяет обходить элементы без ручного вычисления нижней границы массива. Использование `numeric` снижает риск переполнения по сравнению с накоплением в целочисленном типе, но результат всё ещё ограничен диапазоном PostgreSQL `numeric`.

**Таблица поведения функции при различных параметрах**

| Входные данные / условие | Результат |
|---|---|
| Аргумент массива `NULL` | `NULL` |
| Ноль аргументов | `NULL` согласно описанному для `STRICT` поведению; фактическая SQL-вызовимость без аргумента определяется сигнатурой |
| Более одного аргумента | `ERROR` при обнаружении лишних аргументов реализацией; SQL-сигнатура сама по себе не допускает такой вызов |
| `{}`, `ndim = 0` или `ndim = 1`, ожидаемый тип | `1` — нейтральный элемент умножения |
| `{A1}` | `A1` после преобразования к `numeric` |
| `{A1, A2, …, An}` | `A1 * A2 * … * An` |
| Массив содержит хотя бы один `NULL` | `NULL` |
| `ndim > 1`, включая пустой массив | `ERROR` |
| Тип элемента не входит в список ожидаемых | `ERROR` |
| `{NaN}` | `NaN` |
| `{Infinity}` / `{-Infinity}` | `Infinity` / `-Infinity` |
| `NaN` присутствует среди элементов | `NaN` |
| `Infinity` или `-Infinity` умножается на конечное ненулевое значение | Бесконечность с соответствующим знаком |
| `Infinity` или `-Infinity` умножается на `0` | `NaN` |
| `{ -Infinity, Infinity }` | `-Infinity` согласно приведённому примеру исходной спецификации |
| Переполнение `numeric` | `ERROR` |

- Длина: произвольная.
- Число измерений: `ndim = 0` или `ndim = 1`.
- Типы элементов: `smallint`, `integer`, `bigint`, `decimal`, `numeric`, `real`, `double precision`.

### `array_avg`

**Общая сигнатура функции:** `array_avg(anyarray) -> numeric`

**SQL-сигнатура:** `array_avg(anyarray) RETURNS numeric`

**C-сигнатура:** `Datum array_avg(PG_FUNCTION_ARGS)`

**Параметры входного массива:**
- Длина: произвольная.
- Число измерений: `ndim = 0` или `ndim = 1`.
- Типы элементов: `smallint`, `integer`, `bigint`, `decimal`, `numeric`, `real`, `double precision`.
- Функция `STRICT`; массив или элемент `NULL` приводит к `NULL`.

**Алгоритмическое решение и пояснение.**

Итератором обходятся все элементы массива. Каждый элемент приводится к `numeric`, сумма накапливается через `numeric_add`, затем сумма делится на количество элементов через `numeric_div`: `avg = sum / n`. Для пустого массива возвращается `NULL`, поскольку среднего арифметического без элементов нет.

**Таблица поведения функции при различных параметрах**

| Входные данные / условие | Результат |
|---|---|
| Аргумент массива `NULL` | `NULL` |
| `{}`, `ndim = 0` или `ndim = 1`, ожидаемый тип | `NULL` |
| `{A1}` | `A1` после преобразования к `numeric` |
| `{A1, A2, …, An}` | `(A1 + A2 + … + An) / n` |
| Массив содержит хотя бы один `NULL` | `NULL` |
| `ndim > 1`, включая пустой массив | `ERROR` |
| Тип элемента не входит в список ожидаемых | `ERROR` |
| `{NaN}` или массив содержит `NaN` | `NaN` |
| `{Infinity}` / `{-Infinity}` | `Infinity` / `-Infinity` |
| В массиве присутствуют `Infinity` и `-Infinity` | `NaN` |
| Переполнение `numeric` или ошибка арифметической операции | `ERROR` |

### `array_min`

**Общая сигнатура функции:** `array_min(anyarray) -> anyelement`

**SQL-сигнатура:** `array_min(anyarray) RETURNS anyelement`

**C-сигнатура:** `Datum array_min(PG_FUNCTION_ARGS)`

**Параметры входного массива:**
- Длина: произвольная.
- Число измерений: `ndim = 0` или `ndim = 1`.
- Поддерживает типы: `smallint`, `integer`, `bigint`, `decimal`, `numeric`, `real`, `double precision`.
- Функция `STRICT`; массив или элемент `NULL` приводит к `NULL`.

**Алгоритмическое решение и пояснение.**

Итератором обходятся элементы массива. Минимум инициализируется первым элементом, затем для каждого следующего элемента вычисляется `min_el = min(min_el, element)`. Для сравнения примитивных типов использовать средства C, для сравнения специфических, например, Numeric, использовать средства PostgreSQL. Результат сохраняет тип элемента массива.

**Таблица поведения функции при различных параметрах**

| Входные данные / условие | Результат |
|---|---|
| Аргумент массива `NULL` | `NULL` |
